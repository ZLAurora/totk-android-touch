# Native CPU profiling: Phase 1 candidates for the Duo

Phase 2 capture/measurement waits for an authorized device slot; Phase 3 implementation requires its results and a separate go decision. No adb/device access, builds, tests, formatters or commits were performed for this report.

## Current implementation: do not propose it twice

1. **Descriptor driver writes already run on recorders.** Walking selects resource versions and fills immutable inputs (`gfx/vk_draw.c:4811-4886`); workers resolve remaining raw ranges, hash payloads, allocate and template-update sets (`gfx/vk_record.c:929-982`). `hash_words`/ordinary writes on the immediate path are not evidence that threaded graphics still does those writes on the walker (`gfx/vk_draw.c:4895-4900,4989-5007`).
2. **Binding freeze already exists.** Its key covers job, submission, uniform/binding/resource/sampler revisions, CPU-dirty epoch, frozen spans, shader, dimensions and native/feedback state. Changed binding revisions already get exact shader-used-value comparisons; changed uniform revisions get range-history checks. Writable stages and unwatched copies cannot be frozen (`gfx/vk_draw.c:4636-4648,4753-4813,4877-4887`). Blindly deleting key fields would remove correctness authority, not overhead alone.
3. **Vertex/index batching already exists.** A secondary accumulates changed contiguous vertex bindings and memoizes index bindings; pipeline/dynamic/descriptor bindings also have local guards (`gfx/vk_record.c:1043-1114`). The historical fixture reduced vertex API calls **93%** and index calls **25.4%**, without reducing actual draws (`VULKAN.md:1763-1781`). Those savings are already in this tree, not a new Duo forecast.
4. **Command-pool handle reuse already exists, but executable-content reuse does not in the ordinary recorder path.** One pool per recording owner supplies cross-slot fence-retired leases (`gfx/vk_record.c:258-340`). Each ordinary job still begins/ends its secondary afresh with `ONE_TIME_SUBMIT` (`gfx/vk_record.c:1035-1042,1116`). Primary worker-mode pools likewise avoid blanket pool reset (`gfx/nvn_vk.c:2363-2374`). Implicit begin still resets the reused buffer's real driver state; a zero `ResetCommandPool` count is not zero reset cost (`VULKAN.md:1737-1746,1778-1793`).
5. **Off-walker assembly and cheap lease maintenance are already present.** The submit owner joins sealed jobs and queues them (`gfx/nvn_vk.c:2614-2647`); retirement publishes a slot lease chain and the recording owner splices it, without return-only wakeups (`gfx/vk_record.c:258-340,1180-1186`). Historical asynchronous-assembly gains are overlap, not deleted work (`VULKAN.md:1940-1970`); historical walking prune/reset costs were also addressed (`VULKAN.md:2366-2419`).

The supplied Thor driver shares—pool reset 12.0%, vertex bind 9.4%, descriptor update 9.3%, refcount atomics 7.2% **of the 14.6% driver share of process CPU**—predate those changes. They are neither percentages of a frame nor transferable Duo milliseconds. The flat atomics profile has no caller attribution; descriptor layout references are only one concrete possible source (`VULKAN.md:1724-1727,1787-1793`). Do not remove lifetime atomics or claim all their samples as savings.

## Ranking: incremental opportunity, not summed promises

Order is **evidence-adjusted implementation priority**, not theoretical maximum. All numerical savings below are **[INFERENCE] screening envelopes**, include zero, and are not measured improvements or statistical confidence intervals. Their historical scaling is explicit; each must be narrowed to at most the relevant **current exclusive CPU cost** after Phase 2. Negative net results remain possible. “Worker CPU” means summed execution, not critical-path wall time.

| Rank | Structural candidate | Plausible CPU saving per native frame | Evidence / decision |
|---|---|---|---|
| 1 | Cheaper walker binding-freeze validation for irrelevant binding changes | **0–0.4 ms walker CPU** [INFERENCE] | A screening target of at most roughly one third of the old 1.14 ms binding leaf, not the whole 2.7 ms texture path or 0.77 ms libc leaf. Existing exact scans must remain the fallback. See candidate A. |
| 2 | Same-job immutable descriptor-list identity before worker copy/hash/lookup | **0–0.5 ms summed worker CPU** [INFERENCE] | About 0–3% of the old 17.2 ms recorder execution budget; repeated list coverage and present hash/copy cost are unknown. This avoids redundant CPU preparation, not all descriptor writes. See candidate B. |
| 3 | Cross-frame executable secondary reuse for a narrowly proven stable subset | **0–1.5 ms summed worker CPU** [INFERENCE, conditional] | If 5–10% of the historical 17.2 ms recorder work were actually eligible, gross removal would be 0.86–1.72 ms before detection/retention costs. No such hit rate is measured. No walker saving is credited merely for skipping worker re-recording. Larger whole-list translation bypass is unquantified. |
| 4 | Further pool-reset / allocation / refcount reduction | **0 ms additional credited** for the already-delivered mechanisms; new residual cost unquantified | Stock is already available, not an absent implementation. Current stack attribution must distinguish descriptor reset, implicit CB reset, cold maintenance and unrelated references. Existing neutral results and memory risks argue against promoting stock. |
| 5 | More vertex/index call batching | **0 ms additional credited** for existing batching; residual unquantified | Current code already emits only changed runs. Genuine per-draw offset/stride changes still require new state. Only reconsider if current samples show meaningful remaining bind cost and packets show legally mergeable changes. |
| 6 | Move remaining descriptor selection/setup off the walker | **0 ms credited aggregate CPU saving**; walker-only reduction uncalibrated | The previously isolated movable metadata/template work was only **0.0477/0.2673 ms/frame stable/churn on the host**; even including all reserve/zero work gave 0.0878/0.4627 ms, an optimistic non-achievable bound, not Duo time (`walker-desc/report.md:89-103`). Selection/protection must still happen at the original stream position. |

**Do not sum this table.** Cross-frame reuse would subsume worker hashing/binding/reset savings for its hits. Better walker freeze hits reduce the descriptor lists and texture work available to other optimizations. Even 0.9 ms summed CPU saved by A+B would not establish 0.9 ms shorter frames, recovered 60 fps, or fewer missed display slots.

### A. Narrow walker binding validation, not a second descriptor offload

Current stage-wide bind revisions change for any UBO/SSBO/texture/sampler/image rebind (`gfx/vk_draw.c:6420-6462`). A shader using only a few bindings can therefore rescan all its used values even when an unrelated slot changed (`gfx/vk_draw.c:4776-4786`). The existing scan already recovers the freeze hit; the incremental opportunity is its **validation cost**, not claiming those misses are all materializations.

A plausible later implementation is a bounded per-binding change journal or per-binding revisions, checked against immutable shader-used dependencies before the existing exact scan. Cover generated-bank inputs and indirect `RB_SBUF_UBO` dependencies, not just direct UBO addresses (`gfx/vk_draw.c:4571-4588,4831-4849,6434-6455`). Overflow, unknown dependency or relevant change falls back to the existing scan/selection. Preserve every resource/content/lifetime key and writable/unwatched rejection; do not extend the packet-offset freeze across jobs or frames.

**Phase 2 go condition:** current walker self/caller samples show material time in these validation scans, with enough unrelated binding changes to remove a useful fraction. If selection/dirty protection or actual relevant changes dominate, reject A; the old texture memo's high hit rate with no per-draw saving is a warning against optimizing counters rather than CPU.

### B. Reuse the identity walking already froze inside one job

A freeze hit copies the same descriptor-list reference into the next draw (`gfx/vk_draw.c:4787-4790`), but the worker still calls `descriptor_set` before discovering the same set is already bound (`gfx/vk_record.c:1062-1067`). That function copies, normalizes and hashes the list again (`gfx/vk_record.c:929-975`). Inputs are appended while building and immutable after dispatch (`gfx/vk_record.c:1352-1367,1400-1417`).

A small per-job/per-stage memo can recognize the exact tuple **job generation + list first/count + descriptor layout/template + frozen spans + lag ticket**, then reuse the materialized set. Keep the content cache for distinct lists with equal values. Reset the identity memo at every new job/context generation; pipeline-layout changes must still invalidate bound-set state, even when the materialized descriptor set is reusable. Collect guards at least once for each applicable job/ticket/span identity. Never treat an equal guest address, layout alone or recycled input-array pointer as that tuple. Do not rewrite a set already referenced by an earlier draw.

**Phase 2 go condition:** recorder self/caller samples show significant copy/hash/cache work here and repeated immutable list references dominate enough draws. If unique per-draw snapshots or actual driver updates dominate, reject B; a larger hash table or more retained stock does not create reuse.

## Cross-frame reuse: identity detection is not proof of safe replay

There are two different proposals:

- **Retain/re-execute a Vulkan secondary after current walking produced equivalent packets.** This may save worker command generation, but walking, ordered side effects and dependency checks still run.
- **Skip translation of an NVN called recording.** This additionally requires proving its incoming/outgoing state and every stream-position dependency. It is much larger: calls are normally flattened into their caller, so NVN call boundaries do not automatically equal recorder job/pass boundaries (`hle_nvn.c:1144-1189,1344-1349,1421-1455`; `gfx/vk_record.c:1400-1440`).

An unchanged NVN handle or body checksum is insufficient. `EndRecording` makes a host copy, but control-memory reuse/token loss retires its identity (`hle_nvn.c:1191-1244,1280-1330`), and **deferred binding resolution subsequently modifies the copied handle arrays at submit time** (`hle_nvn.c:2084-2124,2535-2543`). `TOTK_CALL_STATS` hashes list bytes and counts repeated called-list draws, excluding nested draw double-counting; it measures repetition, not safe Vulkan replay coverage (`hle_nvn.c:1347-1379`). No repeated-list percentage from it was supplied here.

Any future reuse admission must prove all of the following, otherwise miss safely:

1. **Immutable arguments and complete state:** exact draw/index/instance parameters, pipeline/layout/shader identity, dynamic values, stream offsets/sizes/strides and inherited incoming NVN state; evaluate deferred handles at the current submit and retain the correct outgoing state. Current walking still decides draw eligibility, touches resources and chooses the pipeline (`gfx/vk_draw.c:5694-5761,5821-5844`). A hash may reject quickly; a hit needs exact identity/version authority, not collision probability alone.
2. **Resources, lifetime and contents where required:** resource incarnations, pool/view/alias mapping generations, sampler/view identity and descriptor-content versions. Mapping identity is not a content version. Existing mapping-only reuse deliberately excludes lag/content classification (`gfx/vk_draw.c:5401-5427`). Raw GPU-read buffers may legitimately contain new data each execution, but the current version's synchronization/guards must still be established; baked/private snapshots must instead refer to the intended immutable bytes. Changed uniform snapshots or recycled arena storage cannot silently hit (`gfx/vk_draw.c:4501-4528,4768-4773,4837-4849,5433-5485`).
3. **Descriptor and executable retention:** retain the exact sets, buffers, views, layouts and command buffer without update/reset/free until every using submission retires. Current per-slot descriptor caches clear at generation handoff, and default pools reset there (`gfx/vk_record.c:710-733,1021-1029`). Keeping a command handle while recycling its descriptors is invalid. Ordinary secondaries use `ONE_TIME_SUBMIT`; a replay design must change the usage/lifetime policy and either serialize re-execution after retirement or legally support overlapping use, never implicitly reset a retained executable (`gfx/vk_record.c:1035-1042`).
4. **Render inheritance and ordering:** compatible attachment count/formats, depth/stencil, sample count, view mask/rendering flags and any active inherited query state. Preserve barriers, load/store operations and primary/secondary order. Current inheritance is captured per job (`gfx/vk_record.c:1036-1042`) and assembly executes jobs in pass order (`gfx/vk_record.c:1453-1477`). Similar-looking geometry or the same shader does not prove this compatibility.
5. **Actual slot/fence ownership:** GPU/post completion **and** submit-owner retirement, plus any replay covering leases. A reservation is not queue publication or completion. Current reuse waits on both busy pins; final retirement releases leases only when all relevant owners are done (`gfx/nvn_vk.c:2275-2298,2643-2647`; `gfx/vk_record.c:320-340`; `VULKAN.md:1826-1831,1850-1861`). Use a bounded cache budget/admission policy; retaining whole old slots is not free memory.
6. **GPU writes and query/other side effects:** storage stores/atomics, image writes, clears, timestamps/query IDs/resets, conditional rendering, reports, write-back and lag registrations must execute once at the correct current position. Initial admission should reject unknown/writable/query-bearing jobs rather than skip their bookkeeping. Current selection marks GPU writes and disallows writable freeze hits; jobs can also contain clear/timestamp events (`gfx/vk_draw.c:4811,4847-4849,4865-4868`; `gfx/vk_record.c:1050-1055,1117,1424-1428,1501-1524`).

Cheap detection may conservatively miss: same retained recording incarnation plus known unchanged dependency versions, immediate rejection of deferred/unknown/writable/query cases, then exact immutable packet identity before retaining a secondary. Unknown journal history or cache eviction is an ordinary miss. Full frame-byte hashing/resource scans may cost more than the re-recording avoided. Without eligible hit coverage and retained-memory measurements, generic cross-frame reuse is **not one of the first two recommended implementations**. Existing specialized frame-generation terminal replay/leases are not proof of generic gameplay-list reuse (`gfx/vk_draw.c:5495-5517,5768-5793`; `VULKAN.md:1850-1861`).

## Neutral results and memory are design constraints

- Later Duo A/Bs found texture memo (77.6% hits), no-copy calls and the combined arm **SAME**; wake polling cut about 1 ms walking time but did not improve frame throughput and increased CPU PSI. More recent restart wake-batch/ADPF results were scene-dependent, not promotable (`.scratch/perf/BACKLOG.md:40-48,174-178`). The switches and their neutral evidence must not be repackaged as fresh wins.
- Uncapped descriptor stock grew pools **32→88**, adding **470 MB KGSL in 5 s** on the Duo. The 1,024-set ceiling cut allocate calls 63% and resets 89% but did not produce an accepted tail win (`.scratch/perf/BACKLOG.md:45-46`). Wave-1 collapse reached 13 fps with severe memory pressure; later sessions also show memory-pressure tails in either build (`.scratch/perf/BACKLOG.md:13-14,119-129`). Cross-frame retention can reproduce this class of regression even if CPU counters improve.
- The stock host result (paired -0.970/-1.736 ms stable/churn, one churn pair regressing 0.419 ms) is already recorded, not a Duo prediction (`.scratch/walker-desc/report.md:109-121`). It does not justify enabling stock by default or attributing all descriptor selection time to movable driver writes.
- T7's instrumentation itself created many long Duo frames; persistent-root-shell tooling reduced them substantially (`.scratch/perf/BACKLOG.md:24-25,48`). No “tail recovered” comparison should use that contaminated baseline.

## Phase 2 and Phase 3 gates

When the authorized slot opens, collect a warmed **current-build** native CPU profile with the exact matching `libtotk.so` build ID and retained symbol provenance; use the pinned NDK simpleperf at `/home/agent/Android/Sdk/ndk/28.2.13676358/simpleperf`. The report tool's contract is `tools/bench/cpuprof_report.py DATA --symbols DIR [--ndk-simpleperf DIR] [--out FILE] [--top N]`, native ReportLib sample-period weighting and per-thread self/inclusive rankings for **walker / recorders / submit / game / other**, not parsed human report text. This document does not claim a capture/report run or verify that implementation.

Normalize CPU execution by native frames actually completed in the same capture window; cycles and percentages alone are not milliseconds. Keep each recorder's self ranking and the aggregate, attribute libc/atomics through callers, and distinguish submit/recorder runnable or join waits using scheduling evidence rather than on-CPU samples. Keep scene, lag, worker/chunk configuration, profile-forced-inline status, caps/thermal policy and memory pressure explicit. Existing diagnostics can force workers off (`gfx/vk_record.c:1237-1242`), so a different recording topology is not a valid control.

Only then choose **A and/or B**, if their go conditions hold; otherwise select neither. Phase 3 needs matched-control host correctness/identity/lifetime checks, then separately authorized device A/Bs with CPU execution, critical-path/frame tails, pixels and retained CPU/KGSL memory. Parent-owned verification should cover the profiling CLI's unittest suite now; future graphics tests must be selected for the actual approved change (binding dependency overflow/alias/writable cases for A; delayed workers, ticket/span identity and slot reuse for B). No speculative graphics change or default switch promotion is part of Phase 1.
